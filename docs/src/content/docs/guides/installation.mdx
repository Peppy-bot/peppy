To install `peppy`, run the following command in your terminal:

```sh
curl -fsSL https://peppy.bot/install.sh | sh
```

Supported platforms:

- **Linux (64-bit x86_64 or aarch64, glibc 2.38+)**: Ubuntu 24.04 or later (and derivatives identified via `ID` or `ID_LIKE` in `/etc/os-release`), Debian 13 or later (`ID=debian` only; Debian derivatives such as Devuan are not supported), and 64-bit Raspberry Pi OS (see [Raspberry Pi](#raspberry-pi)). Tested on Ubuntu 24.04.
- **macOS**: Apple Silicon.

The installer checks the package architecture (`dpkg --print-architecture`, since a 64-bit kernel can run a 32-bit userland) and glibc version (`getconf GNU_LIBC_VERSION`, since Ubuntu derivatives use independent release numbers). On unsupported systems (32-bit, glibc < 2.38 such as Ubuntu 22.04 or Debian 12, Fedora, Arch Linux), the installer exits cleanly before changing anything.

What the installer sets up:

- **CLI binary**: places `peppy` on your `PATH`.
- **Container prerequisites (Linux)**: runs `peppy container setup` to install `uidmap`, `squashfs-tools`, and `fuse2fs`, plus an AppArmor profile where user namespaces are restricted ([Containers](/advanced_guides/containers/#setup-linux)). This also works inside bare Docker or Podman images (`ubuntu:24.04`, `debian:trixie`); inside a container, host service setup (D-Bus/linger) is skipped, and non-root daemons run container nodes from unpacked images ([Node images on overlayfs](/advanced_guides/containers/#node-images-on-overlayfs)).
- **Background service and repository index**: installs the `peppy` user service and indexes the default repositories. Set `PEPPY_NO_SERVICE_INSTALL=1` to skip both; name-based launches will then fail with `nodes.json5 not found or empty` until you run `peppy repo init` and `peppy repo update`.

:::note
To install a specific version, set `PEPPY_VERSION`:

```sh
curl -fsSL https://peppy.bot/install.sh | PEPPY_VERSION="v0.20.0" sh
```
:::

To install from a local release archive instead of downloading one:

```sh
curl -fsSL https://peppy.bot/install.sh | sh -s -- ./peppy-x86_64-unknown-linux-gnu.tgz
```

If a daemon is already running, the installer prompts before replacing it. Set `PEPPY_FORCE_REINSTALL=1` for non-interactive installs.

Each Peppy release reads the hub tags published for that version (see [Repositories](/advanced_guides/repositories/)). Upgrading or downgrading Peppy updates the default hub content automatically on the next daemon start.

### Raspberry Pi

Supported boards are those using the **BCM2712** SoC: **Raspberry Pi 5**, **Raspberry Pi 500**, and **Compute Module 5**. The installer checks `/sys/firmware/devicetree/base` (`compatible` must contain `raspberrypi,` and `brcm,bcm2712`). Older boards (Raspberry Pi 4, 3, etc.) are rejected regardless of OS.

On supported boards, install **Raspberry Pi OS (64-bit)** based on Debian 13 (`trixie`) or later via [Raspberry Pi Imager](https://www.raspberrypi.com/software/), or any supported Ubuntu/Debian distribution above. On Raspberry Pi OS (detected via `/etc/rpi-issue`), the installer stops before making changes if:

- The device tree names no Raspberry Pi board.
- The OS is 32-bit (`armhf` userland, even on a 64-bit kernel).
- The OS is based on Debian 12 (`bookworm`, listed as Legacy in Raspberry Pi Imager), which ships glibc 2.36.

### Installer environment variables

| Variable | Effect |
| --- | --- |
| `PEPPY_VERSION` | Version to install (default: latest) |
| `PEPPY_HOME` | Install prefix (default: `~/.peppy`) |
| `PEPPY_BIN_DIR` | Binary install directory (default: `$PEPPY_HOME/bin`) |
| `PEPPY_REPOURL` | Base URL for downloads (default: `https://peppy.bot`) |
| `PEPPY_DOWNLOAD_URL` | Override the full download URL |
| `PEPPY_NO_PATH_UPDATE` | Skip updating shell `PATH` config |
| `PEPPY_FORCE_REINSTALL` | Skip confirmation prompt when a daemon is running |
| `PEPPY_NO_ROOT_INSTALL` | Never run `sudo` or install packages. Fails with install commands if required container packages are missing (`fuse2fs` warns only). Leaves AppArmor setup to `peppy container setup`. |
| `PEPPY_NO_SERVICE_INSTALL` | Skip service installation and repository init/refresh |
| `PEPPY_NO_CONTAINER_SETUP` | Skip Apptainer container setup and package installation |

## Updating Peppy

To update an existing installation to the latest release:

```sh
peppy update
```

`peppy update` checks the latest release before it downloads the archive. If your installation is already at the latest release, it exits without changing the binary or restarting the daemon. When a newer release is available, `peppy update`:

1. Downloads the release archive and checks its gzip checksum.
2. Runs the new `peppy --version`, and stops before it changes anything if the new binary does not run on this machine or is not the release that it installs.
3. Stops and uninstalls the background service if one is installed at the level of the update (user-level, or system-wide when you run it with sudo).
4. Replaces `peppy`, `zenohd`, and the bundled Apptainer and Lima in the installation directory. If a replacement fails, it puts the previous files back and starts the service again.
5. On Linux, runs `peppy container setup`.
6. Syncs the default repositories (`peppy repo init`).
7. If it stopped the background service: installs and starts the service with the new binary, then refreshes the repository indexes (`peppy repo update`).

A failure in step 5 or 6 does not stop step 7. If a step from 5 to 7 fails, `peppy update` names each step that did not complete, with the commands that complete it. If a system-wide service is installed and you run `peppy update` without sudo, or if no service is installed, `peppy update` does not restart a daemon or refresh the repository indexes: restart the daemon that runs, if there is one, then run `peppy repo update`.

`peppy update` reads the installer variables of the table above:

- `PEPPY_NO_ROOT_INSTALL`: it runs `peppy container status --packages` in place of `peppy container setup`, uses no sudo, and fails when a package that container builds need is missing.
- `PEPPY_NO_CONTAINER_SETUP`: it skips step 5.
- `PEPPY_NO_SERVICE_INSTALL`: it skips steps 3, 6, and 7.

If the background daemon currently runs user nodes, `peppy update` prompts before stopping the daemon. An idle daemon restarts without a prompt.

If an update stops before it completes (for example, with Ctrl-C), the next `peppy update` removes the files that it left in the installation directory. Two `peppy update` commands cannot run at the same time on one installation.

Available flags:

| Flag | Effect |
| --- | --- |
| `--check` | Check the latest release without downloading or installing |
| `--version <version>` | Install a specific release version (for example, `peppy update --version v0.39.0`) |
| `--force` | Reinstall even when already at the target version |
| `-y`, `--yes` | Skip confirmation prompts when active user nodes are running |

## Verifying the installation

The service installs at user level by default; run `peppy service install` with sudo for a system-wide install. The snippets below assume the default user-level install. You can verify the service is running with:

<Tabs>
  <TabItem label="Linux">
    ```sh
    systemctl --user status peppy
    ```
  </TabItem>
  <TabItem label="macOS">
    ```sh
    launchctl list bot.peppy
    ```
  </TabItem>
</Tabs>

<details>
<summary>**Managing the service (optional)**</summary>

`peppy` ships its own platform-independent service commands, which are what the installer itself runs:

```sh
peppy service install     # install the background service
peppy service stop        # stop it
peppy service uninstall   # remove it
```

To drive the service through the platform's own service manager instead:

<Tabs>
  <TabItem label="Linux">
    Start the service:
    ```sh
    systemctl --user start peppy
    ```

    Stop the service:
    ```sh
    systemctl --user stop peppy
    ```

    Restart the service:
    ```sh
    systemctl --user restart peppy
    ```
  </TabItem>
  <TabItem label="macOS">
    Start the service:
    ```sh
    launchctl load ~/Library/LaunchAgents/bot.peppy.plist
    ```

    Stop the service:
    ```sh
    launchctl unload ~/Library/LaunchAgents/bot.peppy.plist
    ```

    Restart the service:
    <Steps>
    1. Unload the service:
       ```sh
       launchctl unload ~/Library/LaunchAgents/bot.peppy.plist
       ```

    2. Reload the service:
       ```sh
       launchctl load ~/Library/LaunchAgents/bot.peppy.plist
       ```
    </Steps>
  </TabItem>
</Tabs>

</details>
