From time to time you might want to run multiple instances of the same node started with different input parameters. For example, a camera node might point to `/dev/video0` on your system while another one points to `/dev/video1`.
Parameters exists to allow you to to run multiple instances of the same node with different input settings.

With the new `parameter` key.

## Synchronizing the interfaces

Now lets try to create a new snapshot of our node in the node stack:
```sh
peppy node add .
```

You'll get an error similar to this one:
```
Error: Fingerprint verification failed: Node config fingerprint mismatch: expected 9a58e1936c52c83d47d31621108e32bb78d2197c2d1989f0001e945a754e29a8, got ca1b1d51711a782db3152a723c6cdc255191c2a1721c7a19088e878fc9879c39. 
The config may have been modified after code generation. Run `node sync` to update the peppygen lib on your node.
```

the reason for this error is that our changes in `peppy.json5` first need to be reflected in our interfaces, this is a protection that ensures that the `peppy.json5` **always** matches the real behavior of the node.
In order to sync the node, run the following command:
```sh
peppy node sync
```
Now try to add the node again:
```
peppy node add .
```
The command should work this time, and you can see the node in the node stack by running:
```sh
peppy stack list
```
