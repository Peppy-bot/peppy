Now that you have PeppyOS installed, let's create your first node. A node is the fundamental unit of computation in PeppyOS - it represents a runnable application or service.
In this guide we will try to understand how the concept of nodes work and how they communicate together.

## Project structure

Run:

<Tabs>
  <TabItem label="Rust">
    ```sh
    peppy node init --build-system rust my_first_node
    cd my_first_node
    ```
  </TabItem>
  <TabItem label="Python">
    :::caution

  </TabItem>
</Tabs>

In the node folder you'll find the following:
 - A `peppy.json5` file
 - A `.peppy` folder local to your machine
 - Your project scaffolding based on the selected build system

## Exploring the `peppy.json5` file
This is the entrypoint and the absolute source of truth of every node. Every node creation and communication is defined by its `peppy.json5` configuration file, regardless of what programming language it's written in. 
A developer that needs to communicate or share a node can simply look at this configuration file and immediately know how the node works without having to dig into the code of the node.
Everything that is present in a `peppy.json5` is meant to be shared & distributed so nothing local to your system should be added in that file.

## The `.peppy` folder
This is a "cache" folder that contains everything automatically generated by the `peppy` daemon/service. Nothing in this folder should be modified by the user and this folder should be added to `.gitignore`.

# Writing your first node
Lets open up the `peppy.json5` file of the node we just created and explore it together.
```
{
  schema_version: 1,
  manifest: {
    name: "my_first_node",
    tag: "0.1.0",
    add_cmd: [
      "cargo",
      "build",
      "--release"
    ],
    start_cmd: [
      "cargo",
      "run",
      "--release"
    ]
  },
  interfaces: {}
}
```

Lets go through the different options:
 - `schema_version`: Always set to version 1 for the moment, it allows the daemon to identify the structure of the configuration file
 - `manifest`: Contains information about the node. Each node is identified by its `name` and `tag`
   - `add_cmd`: Command run when the node is added to the Node stack (more on this later). This is typically the place where you want to run heavy operations like code compilation.
   - `start_cmd`: Command run when a node instance is started
 - `interfaces`: This is where the interfaces that communicate with the other nodes is defined

Lets modify this configuration file to expose a topic that will be sending a "hello world" message.

```
{
  schema_version: 1,
  manifest: {
    name: "my_first_node",
    tag: "0.1.0",
    add_cmd: [
      "cargo",
      "build",
      "--release"
    ],
    start_cmd: [
      "cargo",
      "run",
      "--release"
    ]
  },
  interfaces: {
    exposes: {
      topics: [
        {
          name: "hello_world",
          qos_profile: "sensor_data",
          message_format: {
            message: "string"
          },
        }
      ],
    }
  }
}
```

In order to reflect those changes to the project, the node needs to "synchronize" with the cache in the `.peppy` folder, in order to do so, run:
```sh
peppy node sync
```

This command will generate the interfaces to use in our source code. We can now modify the code and access those interfaces:
