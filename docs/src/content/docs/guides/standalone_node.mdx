Constantly adding and running nodes through the node stack is highly inefficient during development. 
In that scenario, you want to be able to run your node as a regular Rust/Python program and use your favorite IDE to debug it.

## Debugging a node

While debugging the nodes based on the logs can be quite helpful, nothing beats the ability to fire up the debugger to inspect the code that is supposed to run inside the Peppy node stack.
To support this, `peppy` can run a node in "standalone mode": it communicates with other nodes in the stack but runs as a regular program outside of it, allowing you to use standard debugging tools.
Let's create a new node:

The standalone object allows us to load parameters from an external JSON file and pass them to the node, which in turn allows us to run our node as a regular Rust/Python program.
Note that the standalone config is completely ignored when a node is run with `peppy node run`; all parameters provided during the `node run` operation take precedence.

## Seeding slots

When a node runs under a daemon, the daemon injects the resolved bindings for its [pairings](/advanced_guides/pairing/), [producer slots](/advanced_guides/topics/#bindings-and-routing), and [observer slots](/advanced_guides/pairing/#observing-several-pairings-through-one-slot). In standalone mode there is no daemon, so you supply those bindings on `StandaloneConfig`:

| Builder | Equivalent launcher / CLI wiring |
|---|---|
| `with_peer_pin(slot, core_node, peer_id, peer_slot)` | Pairs a `depends_on.pairings` slot with a peer instance. |
| `with_peer_pin_in_copy(slot, core_node, peer_id, peer_slot, copy_name)` | Same as `with_peer_pin`, tagging the peer as belonging to a launcher copy. |
| `with_bound_producer(slot, core_node, producer_id)` | Binds a `depends_on.nodes` or `depends_on.contracts` slot to a producer instance. |
| `with_bound_producer_in_copy(slot, core_node, copy_name, fragment_id)` | Same as `with_bound_producer` for a producer inside a copy (resolved as `<copy_name>_<fragment_id>` with copy metadata). |
| `with_vacant_producer_slot(slot)` | Marks a `zero_or_one` producer slot intentionally vacant (`{ vacant: "..." }`). |
| `with_observed_source(slot, core_node, source_id, source_slot)` | Adds a source to a `depends_on.pairing_observers` slot. |

<Tabs>
  <TabItem label="Python">
```python
standalone_config = (
    StandaloneConfig()
    .with_parameters(params)
    .with_peer_pin("arm", "core_x", "arm_1", "controller")
    .with_bound_producer("camera", "core_x", "front_camera")
    .with_vacant_producer_slot("greeter")
    .with_observed_source("watch", "core_x", "arm_1", "controller")
)
```
  </TabItem>
  <TabItem label="Rust">
```rust
let standalone_config = StandaloneConfig::new()
    .with_parameters(&params)
    .with_peer_pin("arm", "core_x", "arm_1", "controller")
    .with_bound_producer("camera", "core_x", "front_camera")
    .with_vacant_producer_slot("greeter")
    .with_observed_source("watch", "core_x", "arm_1", "controller");
```
  </TabItem>
</Tabs>

Slot rules in standalone mode match launch validation:

- **Repeated calls accumulate in order** for multi-cardinality slots (matching repeated `--link` flags).
- **Cardinality is enforced at startup**: `one` needs exactly 1 entry, `one_or_more` needs at least 1, `zero_or_more` may be omitted, and `zero_or_one` needs either 1 entry or `with_vacant_producer_slot(...)`.
- **Unknown `link_id`s** log a warning and are ignored rather than crashing startup.

## Choosing the clock

Use `with_clock(ClockBinding)` to select the node's [clock domain](/advanced_guides/system_clock/#clock-domains) in standalone mode:

| Binding | Role |
|---|---|
| `ClockBinding.wall()` | Default OS wall clock. |
| `ClockBinding.consumer(domain, domain_core, incarnation, pub_core, pub_id)` | Reads a simulated clock domain published by another instance. |
| `ClockBinding.publisher(domain, domain_core, incarnation)` | Publishes a simulated clock domain (enables `ClockPublisher.for_node`). |

```python
from peppylib.clock import ClockBinding

standalone_config = (
    StandaloneConfig()
    .with_parameters(params)
    .with_clock(
        ClockBinding.consumer("simulation", "core_x", 1, "core_x", "simulation_inst")
    )
)
```
