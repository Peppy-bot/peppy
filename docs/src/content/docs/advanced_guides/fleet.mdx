The **fleet** is the set of robots managed by a stack's coordinating daemon. Each [copy](/guides/launch_files/#copies) in the launch counts as one robot (including controllable devices like a smart appliance or fixture); standalone instances outside copies are not part of the fleet.

The coordinating daemon serves fleet management through the built-in `robot_leases:v1` daemon interface, which provides:
- **Fleet listing** (`list`, `contract`): discover running robots, their instances, and their pinned contracts.
- **Leases** (`lease`, `take`, `release`, `offer`, `open`, `close`): grant one client exclusive permission to move a robot.
- **Move checks** (`check_move`): verify whether a caller may execute a motion command.
- **Halt** (`halt`, `clear_halt`): immediately revoke all leases and block motion calls stack-wide.
- **Change stream** (`changes`): real-time ordered feed of fleet state transitions.

| Client | How it uses `robot_leases:v1` |
| --- | --- |
| Built-in MCP server | Calls `check_move` before invoking any `moves_robot` tool and watches `changes` to cancel active goals on halt ([Members that move a robot](/advanced_guides/mcp/#members-that-move-a-robot)). |
| `peppy node call` | Same check and halt tracking as MCP, acting directly for the operator ([Calling a running instance](/advanced_guides/calling_instances/)). |
| Lease holder node (`depends_on.daemon`) | Runs `lease`, `take`/`release`/`offer`/`open`/`close`, `changes`, and `check_move` within its launcher scope ([Daemon targets](/advanced_guides/core_node_functions/#daemon-targets)). |
| `peppy fleet` CLI | Lists the fleet, triggers a halt, and clears a halt ([The command line](#the-command-line)). |

:::caution
Leases and the halt are **cooperative coordination tools** to prevent software clients from fighting over the same robot. They are **not** a safety system; physical e-stops and certified safety layers remain responsible for safety.
:::

Every call to the daemon is cryptographically signed by its caller; the daemon enforces scopes and lease ownership against that verified sender identity ([The senders of the calls to a daemon](/advanced_guides/call_senders/)).

## Members that move a robot

Contracts tag any member that moves a robot or changes physical device state with `marks: ["moves_robot"]` ([Marks](/advanced_guides/contract_implementation/#marks)). Every MCP server, `peppy node call`, and lease holder calls `check_move` before invoking a marked member. Downstream skill or driver nodes do not re-check leases themselves because their caller already did.

`check_move` accepts either `instance` (the target instance ID) or `robot` (robot name, for clients streaming directly), is callable by any sender without a scope, and returns the current fleet `revision` plus an optional `refusal`:

| Fleet state | `check_move` result |
| --- | --- |
| Stack is halted | Refused with `halted` (even for instances outside copies). |
| Instance outside any copy | Allowed. |
| Robot lease is `open` | Allowed for any client. |
| Robot leased by caller | Allowed. |
| Robot leased by another client | Refused with `leased` (names holder and lease name). |
| Robot has no lease | Allowed for non-lease-holders (MCP, CLI); refused for active lease holders with `not_leased` (must `take` first). |

## The fleet listing

`list` (and `peppy fleet list --json`) returns the complete stack snapshot:

- **Stack metadata**: `version` (Peppy release tag or `unknown`), `core_node` (coordinator), `launcher`, `halted`, `halted_by`.
- **`robots`** (sorted by name): `name`, `option`, `core_node`, `kind` (`simulated` if all instances read a simulation clock, else `physical`), `clock`, `software` (`running` when every instance process across all machines is running, else `stopped`), `robot_commander` (the copy's option on the launcher axis marked `role: "robot_commander"`, which drives its robot outside leases and the halt), `instances` (fragment `name`, runtime `instance` ID, `core_node`, `node`, `node_tag`), and `contracts` (`name`, `tag`, `sha256`, `instances`).
- **`leases`** (sorted by robot): `robot`, `holder` + `holder_core_node`, `name`, `open`, optional `giver` + `giver_core_node` (if transferred via `offer`), and optional `receiver` + `receiver_core_node` (pending offer).
- **`options`, `documents`, `nodes`**: joinable `robot_membership` options/features, pinned contract documents, and all launch nodes/commits across machines.

`contract(name, tag, sha256)` returns the raw pinned contract JSON5 document (refused with `rejected` if unknown), letting clients parse schemas and descriptions via the [codec API](/advanced_guides/codec_api/#parse-a-contract).

## Leases

Only nodes granted `lease` in their `robot_leases` scope can hold leases (MCP servers and the CLI never hold leases):

- **`lease` (long-running action)**: Establishing one `lease` goal makes a process an active lease holder (max one per process; a restarted process's new goal supersedes the old one). Its feedback streams `offer`, `offer_end`, `lease_end`, and `lease_back` events with `robot`, `giver`, and `cause`.
- **`take(robot, name)`**: Claims an exclusive lease on `robot` under a display `name`. Refused with `leased` (unless offered to you), `precondition_failed` (no active `lease` goal, or robot is being removed), `rejected` (unknown robot), or `halted`.
- **`release(robot)`**: Releases your lease. If you received the lease via `offer`, ownership automatically returns to the original `giver`.
- **`offer(robots, receiver)`**: Offers leases you took yourself to another launch instance (transferred leases cannot be re-offered). The `receiver` atomically takes ownership by calling `take`. Offers end automatically on take, release, re-offer to another receiver, or if either side disconnects.
- **`open(robot)` / `close(robot)`**: Temporarily allows any client to move your leased robot while you retain the lease (`close` restores exclusivity).

**Lease lifetime:** Leases end on `release`, `halt`, process exit, `lease` goal end, new launch, or `peppy stack reset` (transferred leases return to their `giver` if the giver is still alive). Restarts never carry over leases. A lease *does* survive if its robot is removed from the stack until released.

**Effect on `join` and `remove`:** Joining under a leased robot's name or removing a robot leased by another client is refused with `leased` (only the holder, or original giver of a transferred lease, may remove it). A lease holder joining a robot via `robot_membership:v1` automatically leases it (and cannot join during a halt).

## The halt

`halt` (or `peppy fleet halt`) immediately stops coordinated motion across the stack:

1. Revokes every lease (without returning transferred leases to givers) and cancels all offers.
2. Persists the halt marker to the daemon's data root so it **survives daemon restarts** (if writing fails, such as a full disk, the in-memory halt still applies until restart and the call returns `attempt_failed`).
3. Blocks all new leases and makes `check_move` refuse every `moves_robot` call with `halted`.
4. All MCP servers, `peppy node call`, and lease holders immediately cancel active `moves_robot` goals and stop sending motion commands (teleop streamers may send a brief measured-pose stop burst to hold position, letting the robot's safety layer take over). Non-motion goals and `lease`/`changes` streams stay open.

Run `clear_halt` (or `peppy fleet clear-halt`) to clear the halt. Clients must re-acquire leases afterward.

## Changes

`changes` is a long-running action that first emits the full fleet listing (`change: "listing"`), then emits one ordered update per fleet event (`join`, `removal`, `software_stop`, `software_start`, `lease_start`, `lease_end`, `lease_open`, `lease_close`, `offer_start`, `offer_end`, `holder_change`, `halt_start`, `halt_end`) along with a monotonically increasing **`revision`**.

Clients compare `revision` numbers between `check_move` and `changes` so only a halt at a *newer* revision than a goal's move check cancels that goal.

## Scopes and raw calls

The daemon enforces access against each call's verified sender:

- **CLI**: Unscoped access to all `robot_leases:v1` members and all raw daemon services.
- **Launch instances**: Only the `robot_leases:v1` members granted in their [`daemon_scopes`](/advanced_guides/core_node_functions/#scoping-a-daemon-target) (remote instances only when placed there by the launch). `check_move` is open to all senders, and `changes` is open to all built-in MCP servers.
- **No raw mutating calls from nodes**: Instances cannot call raw mutating daemon actions/services (launch, join, remove, build, run, reset, stop, repo edits); these are refused with `rejected`. Nodes retain access to read-only and runtime services (clock, datastore, health, info, stack list, node info, instance documents, repo list).

## Federation

In a [federated](/advanced_guides/federation/) launch, the **coordinator** serves `robot_leases:v1` and `robot_membership:v1` for the entire fleet:

- Every participant daemon reports instance starts/stops to the coordinator and refuses direct `robot_leases:v1`/`robot_membership:v1` calls with `precondition_failed` (naming the coordinator).
- Daemon targets on instances running on any machine automatically bind to the coordinator.
- `peppy fleet` and `peppy node call` automatically discover and contact the launch coordinator, so halting from any machine halts the entire fleet.

## The command line

| Command | Action |
| --- | --- |
| `peppy fleet list [--json]` | Prints launcher, halt state, and each robot's option, machine, kind, software state, commander, and lease. |
| `peppy fleet halt` | Halts the stack. |
| `peppy fleet clear-halt` | Clears the halt. |

`peppy node call`, `peppy stack join`, and `peppy stack remove` exit with code `3` whenever a lease or halt refuses the operation.
