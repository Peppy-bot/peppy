v0.16.0 https://docs.peppy.bot/releases/v0-16-0/ 2026-07-13T00:00:00Z Renames interfaces to contracts, tightens `depends_on` slot validation, and fixes macOS container builds. <article> <header> <h1>v0.16.0</h1> <p><em>Renames interfaces to contracts, tightens `depends_on` slot validation, and fixes macOS container builds.</em></p> <p><small> Released on July 13, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>The <code>conforms_to</code> manifest field has been renamed to <code>implements</code> as part of a broader rename of "interfaces" to "contracts"; rename <code>conforms_to</code> to <code>implements</code> in your <code>peppy.json5</code> and update any "interface" wording to "contract".</li> <li>Dependency slots (<code>depends_on</code>) now require a single producer each, replacing the previous <code>from_any</code> binding model, and peppy now fails validation whenever a <code>depends_on</code> slot is left unfulfilled; update your bindings so every slot names exactly one producer.</li> </ul> <h3>Container builds and runs (macOS)</h3> <ul> <li>macOS container builds no longer silently default to <code>$HOME</code> and now use the current working directory.</li> <li>The peppy data root is now mounted into the Lima VM so container builds and runs can access it.</li> <li>Fixed a hang where restarting the Lima VM blocked the async runtime while registering a host mount for the first time.</li> <li>Container Python bindings no longer ship stale native extensions after shared-crate changes.</li> </ul> <h3>Validation and output</h3> <ul> <li>Contract (<code>implements</code>) validation failures now report per-slot coverage mismatches instead of a single combined string.</li> <li>The CLI info output formatting has been simplified.</li> </ul> <h3>Documentation</h3> <ul> <li>The advanced guides now include Python examples alongside the existing Rust examples.</li> <li>The Python async examples now wrap <code>select!</code> in a loop and hold references to asyncio tasks so they are not cleaned up or garbage-collected prematurely.</li> </ul> </article>
