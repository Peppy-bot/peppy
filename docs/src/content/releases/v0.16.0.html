Every node must be migrated and every fleet resynced. <article> <header> <h1>v0.16.0</h1> <p><em>Breaking: <code>interfaces.conforms_to</code> is replaced by <code>manifest.implements</code> with explicit per-member entries, and the wire discriminator renames from <code>interface</code> to <code>contract</code>. Every node must be migrated and every fleet resynced.</em></p> <p><small> Released on July 12, 2026 </small></p> </header> <h3>Contract implementation replaces contract conformance (breaking)</h3> <ul> <li>The <code>interfaces.conforms_to</code> field is removed from <code>node/v1</code>. A manifest still carrying it fails to parse with the plain unknown-field error.</li> <li>Contract claims now live in <code>manifest.implements</code>: one entry per contract with <code>{ name, tag, link_id, sha256? }</code>. The <code>link_id</code> shares one flat namespace with <code>depends_on</code> link_ids.</li> <li>Every member of an implemented contract must be listed explicitly in the node's <code>interfaces</code> section as a contract-backed entry <code>{ link_id, name }</code> under <code>topics.emits</code>, <code>services.exposes</code>, or <code>actions.exposes</code>. Shape and QoS come from the contract document; inline shape fields on a contract-backed entry are rejected.</li> <li>Full coverage is mandatory and enforced at <code>node add</code> / <code>node sync</code>: missing, unknown, duplicated, and wrong-kind entries are reported in one aggregated diff per implements slot.</li> <li>Node dependencies now expose native interfaces only: a consumed entry whose <code>link_id</code> names a <code>depends_on.nodes</code> slot resolves exclusively against the producer's native declarations. Contract-backed interfaces are consumable solely through <code>depends_on.contracts</code>.</li> <li>The launcher's binding predicate is unchanged in shape but reads <code>manifest.implements</code>; the mismatch error renamed from <code>BindingContractNotConformed</code> to <code>BindingContractNotImplemented</code>.</li> <li>See the rewritten <a href="/advanced_guides/contract_implementation/">Contract implementation</a> guide (previously "Contract conformance").</li> </ul> <h3>Wire format rename (breaking)</h3> <ul> <li>The keyexpr discriminator segment for contract-addressed traffic renames from <code>interface</code> to <code>contract</code>. Old and new nodes cannot interoperate on contract-addressed topics, services, or actions.</li> <li>Generated code and peppylib rename accordingly: <code>SenderTarget::interface(..)</code> is now <code>SenderTarget::contract(..)</code> (Rust) and <code>SenderTarget.contract(..)</code> (Python).</li> </ul> <h3>Migration runbook</h3> <ol> <li>For each node with <code>interfaces.conforms_to</code>: move every entry to <code>manifest.implements</code> and mint a semantic <code>link_id</code> per slot (e.g. <code>cam</code>, <code>moves</code>, <code>hw_ready</code>).</li> <li>Add one explicit contract-backed entry <code>{ link_id, name }</code> per contract member to the node's <code>interfaces</code> section: contract topics under <code>topics.emits</code>, contract services under <code>services.exposes</code>, contract actions under <code>actions.exposes</code>. Coverage must be complete.</li> <li>Run <code>peppy repo refresh</code>, then <code>peppy node sync</code> every node (or re-add). The wire rename means partially-migrated fleets do not interoperate: resync and restart everything in one coordinated pass.</li> <li>Regenerate all peppygen output; stale generated code referencing <code>SenderTarget::interface</code> will not compile against the new peppylib.</li> <li>Python nodes: rebuild the peppylib extension (<code>uv sync --reinstall</code> or equivalent) so the <code>.so</code> matches the new wire format.</li> </ol> </article>
