v0.18.0 https://docs.peppy.bot/releases/v0-18-0/ 2026-07-23T00:00:00Z Adds observer slots, unifies binding and pairing into links, reworks zenoh config, and spans stack list across daemons. <article> <header> <h1>v0.18.0</h1> <p><em>Adds observer slots, unifies binding and pairing into links, reworks zenoh config, and spans stack list across daemons.</em></p> <p><small> Released on July 23, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>The <code>peppy auth</code> command group is renamed to <code>peppy platform</code>; update any commands or scripts that call <code>peppy auth</code>.</li> <li>The <code>--bind</code> and <code>--pair</code> flags are replaced by a single <code>--link</code> flag; switch your commands to use <code>--link</code>.</li> <li>Launch files now use unified <code>links</code> and <code>defer_links</code> fields in place of the previous separate binding and pairing entries; migrate your launch files to the new fields.</li> <li>Zenoh settings in <code>peppy_config.json5</code> are restructured into a <code>zenoh</code> section with tagged <code>zenoh.managed</code> and <code>zenoh.external</code> blocks, replacing the flat <code>zenoh</code>, <code>zenohd</code>, and <code>peer</code> fields, and unknown fields under <code>zenoh</code> are now rejected; move your settings into the new blocks. The new <code>zenoh.external</code> block lets peppy run against an operator-managed zenoh router.</li> <li><code>peppy stack list</code> no longer prints DOT graph output; it now always renders a report of per-core-node sections aggregated across every live daemon, including live instance counts and the answering daemon's identity, so update anything that parsed the old graph output.</li> <li>Generated peppygen modules for slots are now nested at <code>&lt;category&gt;/&lt;link_id&gt;/&lt;member&gt;</code>; update the import paths for your generated code.</li> <li>The <code>PEPPY_DAEMON_STATE_FILE</code> environment override is removed; the daemon state file now lives under <code>$PEPPY_HOME</code>, so stop setting <code>PEPPY_DAEMON_STATE_FILE</code>.</li> <li>The "organization"/"org-id" concept is renamed to "workspace"/"namespace" across authentication and daemon output; update references and scripts that use the old terms.</li> </ul> <h3>Observers</h3> <ul> <li>Nodes can now declare observer slots to observe topics, with generated observer bindings (including an <code>ObservedSource</code> type) and delivery of observers to running nodes.</li> <li>Guides and launch-file documentation now cover observer slots and the <code>links</code>/<code>defer_links</code> model.</li> </ul> <h3>Multi-daemon and federation</h3> <ul> <li>Daemons can participate in a federated peer topology across zenoh routers.</li> <li>Federation-aware CLI commands now surface listener and serve errors instead of hanging.</li> </ul> <h3>Other changes</h3> <ul> <li>Removing a node with <code>node remove --stop-instances</code> now also dissolves that node's links.</li> <li>A new <code>PEPPY_CONFIG</code> environment variable overrides the daemon config file path.</li> <li>Only one peppy daemon can run per <code>$PEPPY_HOME</code> data root, enforced by an exclusive singleton lock.</li> <li>Config drift now logs which <code>peppy_config.json5</code> settings it adds when completing missing defaults.</li> <li>Newly generated core-node default names use the compact <code>cn-{adj}-{surname}</code> format instead of the longer <code>core-node-{adj}-{surname}-{4digits}-{10digits}</code> form.</li> <li>The bundled Cap'n Proto compiler is now installed under <code>$PEPPY_HOME/bin</code>, and its location is documented.</li> </ul> <h3>Documentation</h3> <ul> <li>External federation guidance adds a dedicated section on namespace handling outside the Peppy platform.</li> </ul> </article>
