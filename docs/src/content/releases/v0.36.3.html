v0.36.3 https://docs.peppy.bot/releases/v0-36-3/ 2026-11-08T00:00:00Z Publish container node images to OCI registries and pull them on other machines instead of building them. <article> <header> <h1>v0.36.3</h1> <p><em>Publish container node images to OCI registries and pull them on other machines instead of building them.</em></p> <p><small> Released on November 8, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>The generated exposed-service method <code>handle_next_request</code> is renamed to <code>handle_requests</code> and now serves requests continuously from one endpoint; after <code>peppy node sync</code>, rename your calls and remove any loop around them.</li> </ul> <h3>Publishing and pulling container nodes</h3> <ul> <li><code>peppy node publish &lt;name&gt;:&lt;tag&gt;</code> builds a container node and pushes its <code>.sif</code> image to an OCI registry, so other machines can pull it instead of building it.</li> <li><code>peppy stack build --publish</code> pushes the image of each container node every machine builds to the registry.</li> <li><code>--platforms linux/amd64,linux/arm64</code> on a publish also builds and pushes the other architecture in an emulated VM.</li> <li>Add an <code>oci</code> repository (<code>peppy repo add oci://...</code>) whose nodes are pulled as prebuilt images rather than built from sources.</li> <li>Set <code>publish_repository</code> in <code>peppy_config.json5</code> to name the OCI repository that publishes push to.</li> <li>Registry credentials come from the Docker or Apptainer auth file, so <code>docker login</code> or <code>apptainer registry login</code> authorizes pulls and pushes.</li> </ul> <h3>Launcher check</h3> <ul> <li><code>peppy launcher check</code> fully verifies launchers with up to 8192 selection combinations, raised from 4096.</li> </ul> </article>
