v0.31.0 https://docs.peppy.bot/releases/v0-31-0/ 2026-09-24T00:00:00Z Serve every robot from one MCP endpoint, start named copies with a launch, and publish lossless 16-bit depth frames. <article> <header> <h1>v0.31.0</h1> <p><em>Serve every robot from one MCP endpoint, start named copies with a launch, and publish lossless 16-bit depth frames.</em></p> <p><small> Released on September 24, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li><code>peppy stack join</code> now takes one <code>OPTION:NAME</code> argument in place of <code>OPTION -i NAME</code>; update commands and scripts that add a copy to a running stack.</li> <li><code>peppy stack resolve</code> previews joined copies with repeatable <code>--join OPTION:NAME</code> (addressed by <code>--with NAME.option</code>), replacing the removed <code>--join</code>, <code>--join-name</code>, <code>--join-with</code>, and <code>--join-set-arguments</code> flags.</li> <li>A bound member's <code>copy</code> is now a <code>CopyTag</code> carrying the copy <code>name</code> and its fragment's instance id, not a plain name string; update readers of <code>member.copy</code> and of <code>stack list --json</code>.</li> <li>The <code>with_bound_producer_in_copy</code> builder now takes the copy name and the fragment's instance id (running the producer as <code>NAME_&lt;id&gt;</code>) instead of the full instance id and copy name.</li> </ul> <h3>Copies at launch</h3> <ul> <li><code>peppy stack launch</code> and <code>peppy stack build</code> accept repeatable, comma-separated <code>--join OPTION:NAME</code> to start named copies with the launch, addressed by <code>NAME.option</code> words and <code>--place NAME@CORE_NODE</code>.</li> <li>A launcher <code>deployments</code> entry on a <code>zero_or_more</code> axis may list no copies, instead describing how every copy of that option is set up for later <code>--join</code> or <code>stack join</code>.</li> </ul> <h3>MCP exposures</h3> <ul> <li>An MCP exposure that declares <code>robots</code> becomes a per-robot surface: one endpoint serving every robot of the stack, where each tool names its robot and resources are published per robot.</li> <li>Image representations add a lossless <code>png16</code> codec for 16-bit single-channel depth frames, usable with <code>on_oversize: "downscale"</code>, and now read frames labeled <code>z16</code>, <code>mono16</code>, or <code>16UC1</code>.</li> <li>An exposure target may select the same topic member several times, each entry with its own resource name, representation, and policies.</li> </ul> </article>
