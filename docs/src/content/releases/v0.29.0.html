v0.29.0 https://docs.peppy.bot/releases/v0-29-0/ 2026-09-16T00:00:00Z Named clock domains a launch selects per instance, hosted alongside wall time with no daemon restart. <article> <header> <h1>v0.29.0</h1> <p><em>Named clock domains a launch selects per instance, hosted alongside wall time with no daemon restart.</em></p> <p><small> Released on September 16, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li> <p><code>peppy service serve</code> no longer accepts <code>--clock-source=wall|sim</code>; a launch now chooses its clock through domains, so remove the flag from your serve commands and scripts.</p> </li> <li> <p>The per-instance <code>framework: { use_sim_time }</code> and <code>framework: { publishes_sim_time }</code> keys are gone; declare domains in a launcher's root <code>framework.clocks</code> and bind each instance with <code>framework: { clock: "&lt;domain&gt;" }</code>.</p> </li> <li> <p>Standalone configuration replaces <code>with_use_sim_time</code> and <code>with_sim_time_participants</code> with a single <code>with_clock</code>, taking a <code>ClockBinding</code> that names the domain the node reads or publishes.</p> </li> <li> <p>The generated test harness replaces its <code>use_sim_time</code> and <code>sim_time_participants</code> config with one <code>clock</code> knob set to <code>wall</code>, <code>consumer</code>, or <code>publisher</code>.</p> </li> <li> <p><code>SimTimePublisher::for_node</code> is renamed <code>ClockPublisher::for_node</code>, and it reports the single domain it supplies through <code>domain()</code> rather than a participant list.</p> </li> <li> <p>One daemon hosts wall time and any number of simulated domains at once, so simulations and wall-time nodes run together and each launch picks its clock without a daemon restart.</p> </li> <li> <p><code>peppy clock list</code> shows every clock domain running across the federation: who publishes each, whether it has ticked, and how many instances read it, with <code>--json</code> for machine output.</p> </li> <li> <p><code>peppy node run --clock &lt;DOMAIN&gt;</code> binds an instance to a running domain and <code>--publish-clock &lt;DOMAIN&gt;</code> starts it as a domain's publisher; both also work with <code>peppy node add --run</code>.</p> </li> <li> <p><code>peppy stack list</code> adds a CLOCK column per instance, and <code>peppy stack resolve</code> reports the clock every instance of a plan reads before anything runs.</p> </li> <li> <p>A producer binding, pairing, or observation whose two endpoints read different clocks is refused before anything starts, at launch, <code>stack resolve</code>, and <code>node run</code> alike.</p> </li> <li> <p>Launcher adjustments gain a <code>set_framework</code> operation that binds a target instance's clock, letting one shared control or recorder fragment run on whichever domain selects it.</p> </li> <li> <p>The generated <code>clock</code> module's <code>now_ns</code> reads whichever clock its instance is bound to, returning a simulated domain's last tick or the machine's own wall time.</p> </li> </ul> </article>
