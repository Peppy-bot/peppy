v0.33.0 https://docs.peppy.bot/releases/v0-33-0/ 2026-10-12T00:00:00Z Set per-node setup budgets, spread copy parts across machines, control the stack over MCP, and build container images faster. <article> <header> <h1>v0.33.0</h1> <p><em>Set per-node setup budgets, spread copy parts across machines, control the stack over MCP, and build container images faster.</em></p> <p><small> Released on October 12, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>Place a joined copy with <code>@CORE_NODE</code> on its spec (<code>peppy stack join openarm:alpha@jetson-1</code>, or <code>--join openarm:alpha@jetson-1</code> at launch); <code>--place</code> naming a <code>--join</code> copy is now refused.</li> </ul> <h3>Node setup budgets</h3> <ul> <li>Declare <code>execution.setup_timeout_secs</code> (1 to 540 seconds) in a node's manifest to set how long the daemon waits for <code>setup</code> to finish after the node is ready; without it the default is 15 seconds.</li> <li>Read the applied setup budget at run time with <code>node_runner.setup_timeout()</code> in Rust and <code>setup_timeout_secs()</code> in Python.</li> <li>A start the daemon gives up after the node answered ready now stops it cooperatively, so the node's shutdown hooks run before it is killed.</li> <li>An in-band stop now cancels an async <code>setup</code> at its next <code>await</code> instead of waiting for setup to finish.</li> </ul> <h3>Copies on multiple machines</h3> <ul> <li>Run the parts of a copy on different machines: <code>OPTION:NAME@CORE_NODE</code> places the copy's base and <code>--with axis=option@CORE_NODE</code> places the instances a feature brings.</li> <li><code>peppy stack list</code> reports each copy's machine and per-part placement, names a join or removal that holds the stack now, and adds a <code>copy_change</code> field to <code>--json</code>.</li> <li>A removal, or the undo of a failed join, stops a copy's instances one at a time across machines, naming each and what it leaves on an offline or reset machine.</li> <li><code>peppy stack launch</code> and <code>peppy stack build</code> prebuild on the coordinator every node a later join can bring; pass <code>--no-prebuild</code> to build on join instead.</li> </ul> <h3>Control the stack over MCP</h3> <ul> <li>An MCP exposure can target the <code>stack_copies:v1</code> daemon interface, letting a client list, add, and remove stack copies over MCP within the options a launcher's <code>daemon_scopes</code> allows.</li> </ul> <h3>Faster container image builds</h3> <ul> <li>Peppy packs every container image with zstd level 3, roughly ten times faster than the previous gzip at the same size; override it with <code>apptainer_build_extra_args</code>.</li> <li>A container build can cache across builds in the per-node directory at <code>PEPPY_NODE_BUILD_CACHE</code>, which no other node's build shares.</li> </ul> <h3>Other improvements</h3> <ul> <li><code>peppy node info</code> now shows each emitted topic's QoS and retention, or the contract or pairing slot a backed topic takes them from.</li> </ul> </article>
