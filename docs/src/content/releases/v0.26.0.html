v0.26.0 https://docs.peppy.bot/releases/v0-26-0/ 2026-08-26T00:00:00Z Serve MCP exposures from the server built into peppy by listing them in a launcher, with no node to generate or build. <article> <header> <h1>v0.26.0</h1> <p><em>Serve MCP exposures from the server built into peppy by listing them in a launcher, with no node to generate or build.</em></p> <p><small> Released on August 26, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li> <p><code>peppy repo exposure</code> is removed, and an exposure is no longer a committed bundle plus a generated MCP server node. Validate exposures with <code>peppy repo index --check --validate-mcp-exposures</code> and delete the old generated artifacts.</p> </li> <li> <p>Serve an exposure from a launcher's <code>source: { exposures: ["&lt;name&gt;:&lt;tag&gt;", ...] }</code> instead of deploying its generated <code>&lt;name&gt;_mcp</code> node; the server built into <code>peppy</code> binds <code>127.0.0.1:&lt;port&gt;</code>, one endpoint per exposure at <code>/&lt;name&gt;/&lt;tag&gt;/mcp</code>.</p> </li> <li> <p><code>peppy mcp catalog &lt;name:tag&gt;</code> prints the catalog an endpoint advertises: every resource, tool, and task with its public name, policies, and derived JSON Schemas.</p> </li> <li> <p>A target's contract <code>sha256</code> is now optional; omit it and the exposure follows the contract as its repository evolves, with each launch pinning the bytes it resolves.</p> </li> <li> <p>One deployment can serve several exposures on a single port, sharing a contract slot when two exposures name the same target and the same contract.</p> </li> <li> <p><code>peppy stack list</code> adds an <code>Instance endpoints</code> table listing each endpoint URL an instance serves.</p> </li> <li> <p>Exposure deployments work in a federated launch: the exposure documents and the contracts they reference are pinned and shipped to the machine hosting the instance.</p> </li> <li> <p>A new default <code>mcp-hub</code> repository resolves the MCP exposure documents a launcher lists.</p> </li> <li> <p>An exposure manifest may carry a <code>labels</code> list of free-form strings for whoever browses the repository.</p> </li> </ul> </article>
