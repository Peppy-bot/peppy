v0.34.1 https://docs.peppy.bot/releases/v0-34-1/ 2026-10-19T00:00:00Z Claim a datastore key with store_exclusive, control subscription buffering, and refresh repositories in parallel. <article> <header> <h1>v0.34.1</h1> <p><em>Claim a datastore key with store_exclusive, control subscription buffering, and refresh repositories in parallel.</em></p> <p><small> Released on October 19, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li><code>peppylib.clock.subscribe</code> now takes a <code>TopicBuffer</code> argument; pass <code>TopicBuffer.KeepLatest</code> (keep the newest ticks, dropping the oldest when full) or <code>TopicBuffer.Backpressure</code> (wait for the reader) on every call.</li> </ul> <h3>Datastore</h3> <ul> <li>Store a datastore key with <code>store_exclusive</code> to make the calling instance its only writer until its process ends, refusing every other instance's <code>store</code> and <code>remove</code> of that key.</li> <li><code>datastore.list</code> returns its entries in key order.</li> </ul> <h3>Testing</h3> <ul> <li>Generated test-harness and pairing-mock subscriptions keep the newest unread messages, so a test can read emitted topics late, or never, without holding up the session.</li> </ul> <h3>Repositories</h3> <ul> <li><code>peppy repo refresh</code> reads up to 8 repositories at once, taking about as long as its slowest repository, and reports discovered items in priority order once every repository is read.</li> </ul> <h3>Node links</h3> <ul> <li><code>peppy node run</code> and <code>peppy node add --run</code> refuse a <code>--link</code> to a target instance with no process (one that is restarting, finished, or failed).</li> </ul> </article>
