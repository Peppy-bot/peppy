v0.31.7 https://docs.peppy.bot/releases/v0-31-7/ 2026-10-01T00:00:00Z The peppy platform commands are rebuilt around workspaces, projects, and enrolling machines in a project's cloud router. <article> <header> <h1>v0.31.7</h1> <p><em>The peppy platform commands are rebuilt around workspaces, projects, and enrolling machines in a project's cloud router.</em></p> <p><small> Released on October 1, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li><code>peppy platform list</code> is removed; <code>peppy platform peers</code> now lists a project's router peers, with columns for peer name, status, certificate expiry, and id.</li> <li><code>PEPPY_API_KEY</code> personal-access-token authentication is removed; sign in with <code>peppy platform login</code> instead.</li> <li>The <code>zenoh.managed.federation</code> block (with <code>connect_timeout_secs</code>) is gone from <code>peppy_config.json5</code>; remove it or the daemon refuses to load the config.</li> <li><code>peppy platform status</code> now reports this machine's enrollment and router link; use <code>peppy platform whoami</code> for the signed-in identity.</li> <li>Run <code>peppy platform login</code> again after upgrading, because the previous credentials file is no longer read.</li> </ul> <h3>Signing in and enrolling</h3> <ul> <li><code>peppy platform login</code> signs you in and then enrolls this machine in a project's cloud router, with <code>--workspace</code>, <code>--project</code>, and <code>--no-enroll</code> to steer it.</li> <li><code>peppy platform enroll</code> joins an already-signed-in machine to a project, <code>--replace</code> mints a fresh identity, and <code>peppy platform unenroll</code> removes it (<code>--local-only</code> deletes only the local record).</li> <li>Enrolling or unenrolling restarts the daemon under the new identity and wipes the running node stack, prompting first unless you pass <code>--yes</code>.</li> <li>The daemon renews the peer certificate automatically while you stay signed in, so an enrolled machine keeps its cloud-router link without manual steps.</li> <li><code>peppy platform logout</code> revokes the session and clears the selection but leaves the machine enrolled, so the daemon stays connected until its certificate expires.</li> </ul> <h3>Workspaces, projects, and the router</h3> <ul> <li><code>peppy platform workspace</code> and <code>peppy platform project</code> (each with <code>show</code>, <code>list</code>, <code>use</code>, and <code>clear</code>) pick the default workspace and project the other commands act on.</li> <li><code>peppy platform router restart</code> applies pending changes such as a removed peer, and <code>peppy platform router start</code> starts a stopped router.</li> </ul> </article>
