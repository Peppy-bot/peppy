v0.14.0 https://docs.peppy.bot/releases/v0-14-0/ 2026-07-02T00:00:00Z Logging in now connects your daemon to a per-user TLS-verified cloud router, and topics move to a new Subscription API. <article> <header> <h1>v0.14.0</h1> <p><em>Logging in now connects your daemon to a per-user TLS-verified cloud router, and topics move to a new Subscription API.</em></p> <p><small> Released on July 2, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>Topic subscriptions no longer use the per-call <code>on_next_message_received</code> method; subscribing now returns a <code>Subscription</code> that you hold and read messages from, so update your node code to use it.</li> </ul> <h3>Authentication and cloud routers</h3> <ul> <li>Logging in now fetches and caches your per-user cloud (zenoh) router configuration and federates your daemon to it live.</li> <li>peppy verifies the router's TLS certificate when you log in.</li> <li>Logging in or out now takes effect immediately, regenerating and restarting the daemon and propagating your organization namespace through it.</li> <li>Fixed a cross-identity organization cache leak, added a daemon restart when the namespace drifts at startup, and hardened login and logout edge cases.</li> <li>The restart warning is now skipped when your daemon stack has no user nodes.</li> </ul> <h3>Releasing</h3> <ul> <li>Added a <code>--skip-prod-cert-check</code> flag to bypass the production-router certificate gate when running a release.</li> </ul> <h3>Topics</h3> <ul> <li>Tightened how subscriptions behave once they are closed, across generated node code and the docs.</li> </ul> <h3>Reliability</h3> <ul> <li>peppy now retries transient <code>ETXTBSY</code> and <code>ENOENT</code> exec errors when extracting the ruff binary during parallel binary extraction.</li> </ul> <h3>Documentation</h3> <ul> <li>Clarified that <code>reconnect_after_secs</code> and <code>repull_after</code> are cache-freshness hints rather than keepalive deadlines.</li> </ul> </article>
