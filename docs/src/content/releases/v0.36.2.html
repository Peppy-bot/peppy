v0.36.2 https://docs.peppy.bot/releases/v0-36-2/ 2026-11-02T00:00:00Z Instances can take named variables from the launch shell with `env_from_launch`, keeping secrets like API keys out of launcher files. <article> <header> <h1>v0.36.2</h1> <p><em>Instances can take named variables from the launch shell with `env_from_launch`, keeping secrets like API keys out of launcher files.</em></p> <p><small> Released on November 2, 2026 </small></p> </header> <ul> <li>Declare the variables an instance takes from the launch shell with <code>env_from_launch</code>, or set them on a shared fragment with a <code>set_env_from_launch</code> adjustment, keeping secrets like an API key out of launcher files.</li> <li>Each launch variable's value reaches only the instances that name it, and the daemon keeps it for the stack so a robot joined later reuses it without re-supplying the secret.</li> <li>An instance with launch variables runs on the coordinator only; a launch or join that places it on a peer is refused, naming the instance and the peer.</li> <li><code>peppy stack resolve</code> names the launch variables a launch needs and flags any instance with launch variables that would run off the coordinator.</li> <li>On macOS, a container node's environment now reaches apptainer over the guest command's standard input in the Lima VM, so values no longer appear in the process list.</li> </ul> </article>
