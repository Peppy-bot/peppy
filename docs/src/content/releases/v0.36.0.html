v0.36.0 https://docs.peppy.bot/releases/v0-36-0/ 2026-10-30T00:00:00Z Documents now require descriptions, the daemon verifies every call's signer, and the fleet interfaces are renamed. <article> <header> <h1>v0.36.0</h1> <p><em>Documents now require descriptions, the daemon verifies every call's signer, and the fleet interfaces are renamed.</em></p> <p><small> Released on October 30, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>Every node, contract, and pairing manifest, each launcher, and each topic, service, and action a node or contract declares now needs a <code>description</code>; peppy refuses a document without one.</li> <li><code>peppy node init</code> now takes a required description argument and refuses to run without it.</li> <li>Daemon targets and exposures that named <code>fleet:v1</code> or <code>stack_copies:v1</code> must now name <code>robot_leases:v1</code> or <code>robot_membership:v1</code>.</li> <li>Rebuild every node with this peppy: the daemon accepts only signed calls and refuses the unsigned calls a node an earlier peppy built sends.</li> </ul> <h3>Descriptions</h3> <ul> <li>Give any message-format field a <code>$description</code>; the codec API, <code>peppy node describe</code>, and the MCP server's published schemas all carry it.</li> <li><code>peppy repo show</code>, <code>peppy node describe</code>, <code>peppy node info</code>, and the codec API now surface the descriptions of a document and its members.</li> <li><code>peppy repo search</code> prints each match's summary, and <code>--text</code> extends the search to the full descriptions, with no regard to case.</li> </ul> <h3>Calling the daemon</h3> <ul> <li>Set <code>machine_certificate</code> in <code>peppy.json5</code> so the daemons of an operator-run federation can prove their calls to one another.</li> <li>A container node no longer sees the data root, and a mount whose source touches it is refused.</li> </ul> <h3>Launch files</h3> <ul> <li><code>peppy stack list</code>, the <code>stack.list</code> API, the <code>robot_membership:v1</code> list, and the MCP <code>stack.list</code> tool now report <code>launch_copies</code>, the copies the launch started.</li> <li>A launcher adjustment's <code>target</code> can now name a list of instances that each take the same changes, not only one instance.</li> </ul> <h3>Other</h3> <ul> <li>A pairing observer receives nothing while its observed source is unpaired, since each pairing emission now carries its peer in the key.</li> <li>In a generated test mock, an interface whose name collides with a mock method, such as <code>stop</code>, is reached as <code>&lt;link_id&gt;_&lt;name&gt;</code>.</li> </ul> </article>
