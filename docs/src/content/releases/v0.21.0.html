<header> <h1>v0.21.0</h1> <p><em>Federated launches span machines, repositories resolve through a committed index, and launchers pin registry sources.</em></p> <p><small> Released on August 3, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>Repository entries now resolve through a committed repository index rather than being resolved ad hoc, and every cache entry is pinned to a git commit; generate and commit the index with the new <code>peppy repo index</code> command, whose <code>--check</code> mode verifies the committed index is up to date.</li> <li>Launcher deployment sources are restricted to <code>name:tag</code> registry references that resolve to node pins, and retired source keys are refused with a migration message, so update your launcher files to reference nodes by registry <code>name:tag</code>.</li> </ul> <h3>Federation</h3> <ul> <li>A federated launch now spans multiple machines through cross-machine dispatch.</li> <li>The launcher places and preflights federated core node links across machines.</li> <li><code>peppy reset</code> rediscovers federated reset targets from the federation instead of from local memory.</li> <li>Cross-daemon pairing peers are stamped with their own core node in display reads.</li> <li>Filesystem-backed repositories cannot participate in federation.</li> </ul> <h3>Pairing and dependencies</h3> <ul> <li><code>depends_on</code> gains a fourth peer-coupling level, <code>pairing_observers</code>, across the daemon and launcher.</li> <li>The surviving instance of a pair still receives the dissolution notice after its partner has already stopped.</li> </ul> <h3>Launcher and launch</h3> <ul> <li>Launcher files accept per-instance <code>env_vars</code>.</li> <li>The launch summary lists every machine's node log files.</li> <li>A coordinator's next launch takes over its own stale reservation through a lease instead of being blocked by it.</li> <li>The caller's environment stays on the caller's machine, so peer builds no longer inherit it.</li> </ul> <h3>Containers</h3> <ul> <li>Each peer prepares its own container bind mounts, and relative container mount sources are forwarded to Lima as absolute paths.</li> <li>Restarts that would kill running containers are refused, and container bind sources are prepared before a participant slice takeover.</li> <li>Apptainer SIF images are FUSE-mounted instead of extracted, with squashfuse bundled alongside apptainer.</li> </ul> <h3>Repositories</h3> <ul> <li><code>peppy repo refresh</code> caches its checkout for reuse, prunes orphaned checkouts, applies filesystem exclusions before reading declared items, and skips re-pushing stack entries whose manifest is unchanged.</li> <li>Repository resolution failures are reported and contained instead of guessed, with clearer failure reports.</li> </ul> <h3>Messaging and code generation</h3> <ul> <li>The Rust and Python generators handle <code>$optional</code> scalars and payload-less feedback topics consistently.</li> </ul> <h3>Documentation</h3> <ul> <li>The documentation is aligned with the current commands, outputs, and behavior.</li> <li>Federation coordination guidance and the producer-link example are clarified, with the example showing separate per-node manifests.</li> </ul> </article>
