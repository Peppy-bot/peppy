v0.27.5 https://docs.peppy.bot/releases/v0-27-5/ 2026-09-03T00:00:00Z node build and stack launch now reuse a cached artifact for unchanged sources, with --rebuild to force a fresh build. <article> <header> <h1>v0.27.5</h1> <p><em>node build and stack launch now reuse a cached artifact for unchanged sources, with --rebuild to force a fresh build.</em></p> <p><small> Released on September 3, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li> <p>Built node artifacts now live at <code>~/.peppy/built_nodes/&lt;name&gt;_&lt;tag&gt;/&lt;fingerprint&gt;.tar.zst</code> (or <code>.sif</code>) rather than <code>~/.peppy/built_nodes/&lt;name&gt;_&lt;tag&gt;.tar.zst</code>; update any scripts that reference the old fixed path.</p> </li> <li> <p><code>peppy node build</code> reuses a stored artifact when the staged sources are byte-identical to an earlier build's, skipping <code>build_cmd</code> or <code>apptainer build</code> and logging <code>Reusing cached build of ...</code>.</p> </li> <li> <p>The cache is a content-keyed directory tree that survives daemon restarts and carries built nodes to any machine booted from the same disk with a matching peppy version, OS, and architecture.</p> </li> <li> <p><code>peppy stack launch</code> reuses cached builds for every deployment, on the coordinator and on every peer, so relaunching the same launcher skips rebuilding unchanged nodes.</p> </li> <li> <p>Pass <code>--rebuild</code> to <code>peppy node build</code> or <code>peppy stack launch</code> to rebuild from the staged sources even when a matching artifact exists, replacing it; this is independent of <code>--force</code>.</p> </li> </ul> </article>
