v0.30.0 https://docs.peppy.bot/releases/v0-30-0/ 2026-09-17T00:00:00Z A pairing slot can hold several peers through a declared cardinality, and `--nv` now renders through the GPU on Jetson boards. <article> <header> <h1>v0.30.0</h1> <p><em>A pairing slot can hold several peers through a declared cardinality, and `--nv` now renders through the GPU on Jetson boards.</em></p> <p><small> Released on September 17, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>A pairing slot states that it may run empty with <code>cardinality: "zero_or_one"</code> instead of <code>optional: true</code>; replace <code>optional: true</code> on every <code>depends_on.pairings</code> entry (the default <code>one</code> still requires a pair).</li> <li><code>peppy repo show</code> and its <code>--json</code> output report each pairing slot's <code>cardinality</code> in place of the former <code>optional</code> flag; update any parser reading that field.</li> </ul> <h3>Pairing</h3> <ul> <li>A pairing slot can hold several pairs: declaring <code>cardinality: "one_or_more"</code> or <code>"zero_or_more"</code> pairs one instance with many peers, read through the generated <code>peers()</code> and published to with <code>publish_to</code>.</li> <li><code>peppy stack list</code> prints one row per pair tagged with each peer's copy, and <code>stack join</code> / <code>stack remove</code> add and dissolve pairs on a running multi slot.</li> <li>An observer link can watch a single pair by naming its other end (<code>watch: "peer_instance/link"</code>) instead of the whole source slot.</li> <li>The generated test harness gives a multi pairing slot <code>&lt;link&gt;_instances</code> and <code>&lt;link&gt;_members</code> knobs that start one mock peer per member.</li> </ul> <h3>Containers</h3> <ul> <li>Passing <code>apptainer_run_extra_args: ["--nv"]</code> now binds the Tegra driver libraries, so a node renders or computes through the GPU on Jetson boards as it does on desktop NVIDIA hardware.</li> </ul> <h3>Other changes</h3> <ul> <li>While a build is quiet, each build-progress line names the last line the build printed and how long ago.</li> <li>A daemon's derived core-node name now takes the form <code>cn-{adjective}-{animal}</code>.</li> </ul> </article>
