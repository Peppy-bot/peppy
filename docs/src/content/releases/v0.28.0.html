<article> <header> <h1>v0.28.0</h1> <p><em>Add and remove named launcher copies on a running stack, with steadier instance health and safer concurrent stack changes.</em></p> <p><small> Released on September 14, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>Component axes no longer accept <code>default</code> or <code>optional</code>; add a <code>deployments</code> entry <code>{ &lt;axis&gt;: "&lt;option&gt;" }</code> to pick which option runs, and use <code>cardinality: "zero_or_one"</code> in place of <code>optional</code>.</li> <li><code>message_format</code> no longer accepts the type aliases <code>float</code>, <code>double</code>, and <code>str</code>; use <code>f32</code>, <code>f64</code>, and <code>string</code> instead.</li> </ul> <h3>Repeatable copies</h3> <ul> <li>Declare a component axis with <code>cardinality: "zero_or_more"</code> to run its options as named copies you start, add, and remove independently under one launcher.</li> <li><code>peppy stack join OPTION -i NAME</code> adds a copy to a running stack, selecting its axes with <code>--with</code>, its machine with <code>--place</code>, and per-instance overrides with <code>--set-arguments</code>.</li> <li><code>peppy stack remove NAME</code> stops one copy and drops it from the stack, leaving every other copy and the stack's own nodes running.</li> <li><code>peppy stack list</code> and <code>peppy stack list --json</code> report each copy's option, host, selection, and instances.</li> <li><code>peppy stack resolve</code> previews a copy joined onto a launch with <code>--join</code>, <code>--join-name</code>, <code>--join-with</code>, and <code>--join-set-arguments</code>.</li> <li><code>peppy stack reset --federated</code> clears the launch from every machine it reached.</li> <li>Fragments can declare their own component axes and reference other fragments across directories within a repository.</li> <li>Constraint and adjustment <code>when</code>, <code>requires</code>, and <code>forbids</code> conditions accept a list of option names per axis, matching any of them.</li> </ul> <h3>Instance health and stack safety</h3> <ul> <li>A running instance is flagged <code>unhealthy</code> only after three consecutive missed health probes, and returns to <code>healthy</code> on the first probe it answers.</li> <li><code>peppy node</code> add, build, run, stop, and remove serialize with stack operations: refused while one holds the stack, and cancelled when <code>stack reset</code> runs after a cleanup window.</li> <li>Cancelling a <code>peppy node</code> add, build, run, stop, or remove now stops the work on the daemon instead of letting it finish unattended.</li> </ul> </article>
