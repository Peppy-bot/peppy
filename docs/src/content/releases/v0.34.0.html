v0.34.0 https://docs.peppy.bot/releases/v0-34-0/ 2026-10-15T00:00:00Z Instances restart under a configurable policy after crashes or health failures, with per-process run logs. <article> <header> <h1>v0.34.0</h1> <p><em>Instances restart under a configurable policy after crashes or health failures, with per-process run logs.</em></p> <p><small> Released on October 15, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li>Failing or unresponsive instances now restart by default (<code>on_failure</code>); declare <code>framework.restart: "never"</code> on a node, launcher, or run to keep the previous no-restart behavior.</li> <li>Run logs are now one file per process named <code>&lt;instance_id&gt;_&lt;timestamp&gt;.log</code>, replacing the single <code>&lt;instance_id&gt;.log</code>; update anything that reads the fixed path.</li> </ul> <h3>Other changes</h3> <ul> <li>Set an instance's restart policy with <code>framework.restart</code> in its <code>peppy.json5</code> or a launcher entry, or with <code>--restart</code>/<code>--max-restarts</code> on <code>peppy node run</code> and <code>peppy node add --run</code>.</li> <li>A restarting instance shows <code>restarting</code> while the daemon backs off and starts a new process under the same id, which keeps its bindings, pairings, and any clock domain it published.</li> <li><code>peppy stack list</code> adds a <code>RESTARTS</code> column, <code>peppy node info</code> reports each instance's policy, restart count, last exit and next start, and <code>peppy stack resolve</code> prints each instance's policy.</li> <li><code>peppy node stop</code> now clears a <code>restarting</code>, <code>finished</code>, or <code>failed</code> instance and cancels any pending restart.</li> <li>The <code>stack.list</code> core node function returns each instance's restart status: policy, origin, restart count, attempt, last exit, and timestamps.</li> <li><code>peppy node remove --stop-instances</code> waits for each instance to exit and force-kills any that do not, warning for each; run without the flag it asks for confirmation first.</li> <li>Re-adding a node with <code>peppy node add</code> names each live or restarting instance and its state before overwriting, and is refused while one is starting.</li> </ul> </article>
