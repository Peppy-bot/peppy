v0.27.4 https://docs.peppy.bot/releases/v0-27-4/ 2026-09-02T00:00:00Z A launch can name one instance its simulated-time source, fed to every machine, with one clock source enforced across the fleet. <article> <header> <h1>v0.27.4</h1> <p><em>A launch can name one instance its simulated-time source, fed to every machine, with one clock source enforced across the fleet.</em></p> <p><small> Released on September 2, 2026 </small></p> </header> <h3>Breaking changes</h3> <ul> <li> <p>In Rust, read a clock tick's instant with <code>tick.time()</code> instead of the <code>tick.time</code> field; Python keeps the <code>.time</code> attribute.</p> </li> <li> <p>Reading simulated time now requires a daemon that serves it, so an instance with <code>use_sim_time: true</code> is refused on a wall-mode daemon instead of running; start it with <code>--clock-source=sim</code>.</p> </li> <li> <p>Declare one launch instance its simulated-time source with <code>framework: { publishes_sim_time: true }</code>; peppy hands its <code>SimTimePublisher</code> every machine of the launch so one clock reaches the whole fleet.</p> </li> <li> <p>Federated launches require every machine to serve the same clock source; a sim/wall disagreement is refused at preflight, naming the machine and the flag that fixes it.</p> </li> <li> <p>A launch may declare only one simulated-time source; a second is refused when the launcher is checked, including by <code>peppy stack resolve</code>.</p> </li> <li> <p>Launch feedback names the simulated-time source, and warns when a declared source runs on a wall launch or when a simulated launch declares none.</p> </li> </ul> </article>
